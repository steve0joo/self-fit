# 03. AI 인수인계: 모델 분석 결과와 통합 규약

백엔드가 AI-Hub 제공 모델 4개를 직접 분석한 결과, 서비스에서 모델이 실행되는 방식, 그리고 모델을 넘길 때 지켜야 할 규약을 정리했습니다. AI 팀이 이 문서만 보고도 "무엇을 어떤 형식으로 주면 바로 붙는지" 알 수 있게 하는 것이 목적입니다. 상세는 `../docs/01-dev-plan.md` D-5, `../docs/03-phase1-design.md` 5.5절·7절.

**분석 범위:** 안구 데이터셋 zip 34GB(소스 3종, 가중치 3개, Docker 이미지 3개), 감정 데이터셋 zip 8GB(Docker 이미지 1개), 데이터 샘플 zip 2개. 코드와 가중치 파일 내부를 직접 읽었고, 실제 추론은 아직 실행하지 않았습니다.

## 1. 모델은 어디서 실행되나
```
BE (localhost:8000) ──HTTP: JPEG 1장──▶ 추론 서버 (localhost:9000, 노트북 GPU) ──▶ 결과 JSON
                                  ├─ MediaPipe 얼굴 검출 (1회)
                                  ├─ L2CS-Net    → yaw, pitch
                                  ├─ EmotionNet  → 감정 7개 확률
                                  └─ Former-DFER → 집중 5개 확률 (16장 모아서 2초마다)
```
- 추론 서버는 백엔드가 만들고 **Docker 컨테이너**로 실행합니다. AI 팀이 서버 코드를 짤 필요는 없습니다. 어느 PC에서든 같은 PyTorch·CUDA 환경이라 모델 검증 결과를 비교할 수 있습니다.
- AI-Hub가 준 Docker 이미지(각 11GB)는 검증 스크립트뿐이라 **쓰지 않습니다.** 가중치 파일과 모델 구조 코드만 가져와 추론 서버에 넣습니다.
- 세 모델은 이미지 1개, 프로세스 1개에 같이 올라갑니다.

## 2. 지금 쓰는 모델과 전처리

**2026-09-04 기준:** 안구(시선·집중) 모델은 AI-Hub 제공 가중치를 그대로 쓰고, **감정 모델은 AI 팀이 파인튜닝 중**입니다. 감정 열은 파인튜닝 결과에 따라 바뀔 수 있습니다.

| | 시선 L2CS-Net | 감정 EmotionNet (파인튜닝 전 기준) | 집중 Former-DFER |
|---|---|---|---|
| 가중치 | `l2cs_trained.pkl` 96MB | `model.pth` 57MB | `former_trained.pth` 144MB |
| 입력 | 얼굴 크롭, 448×448 RGB, ImageNet 정규화 | 얼굴 크롭, 48×48 흑백, 0~1 | 얼굴 크롭 16장, 112×112 RGB, 0~1 |
| 출력 | yaw, pitch 각도 | 원본 7클래스 (기쁨 당황 분노 불안 상처 슬픔 중립 순) → **서비스는 4클래스만: 중립, 불안, 당황, 기쁨** | 5클래스 |
| 얼굴 크롭 여백 | 박스 + 20% **(가정)** | 없음 | 없음 **(가정)** |

근거의 강도:
- **확인됨**: 가중치 크기(직접 추출), 입력 크기와 정규화(검증 스크립트 코드), 출력 형식(모델 마지막 층), EmotionNet 클래스 순서(`emotion.py`), EmotionNet 크롭 규칙(`cropImages.py`).
- **가정**: L2CS 크롭 여백(NIA 코드에 없음, 원저자 데모 관례), Former-DFER 크롭 여백과 클래스 순서(근거 없음). → 3절에서 확인 요청.

가중치가 작아 보이는 건 정상입니다. 파일 크기 = 파라미터 수 × 4바이트이고, ResNet50 약 2,400만 개 = 96MB로 계산값과 일치합니다. AI-Hub Docker 이미지가 11GB였던 건 OS·conda·PyTorch 때문이지 모델 때문이 아닙니다.

## 3. AI 팀에 확인 부탁

### 3.1 샘플 데이터로 확인된 것 (2026-09-04, `Sample (1).zip`, `New_sample_3 (1).zip`)
| 항목 | 확인 내용 | 결론 |
|---|---|---|
| 안구 데이터 원본 | 1920×1080 전체 프레임 PNG. 라벨 JSON에 **얼굴 박스 없음** (홍채 타원, 눈꺼풀 폴리곤, 눈 중심점, `pose.head`, `condition`만 있음) | NIA 쪽도 검출기로 얼굴을 잘랐다는 뜻. 여백 값은 데이터로 알 수 없음 → **실측으로 정함** (3.3절) |
| 시선 정답 | `pose.head` = [roll, pitch, yaw] 3개 값, `pose.point` = 화면 응시 좌표 | L2CS 출력 검증용 정답으로 사용 가능 |
| 집중 상태 라벨 | `condition` 필드. 샘플에는 `A`(218장), `D`(104장)만 있음 | 클래스 순서는 샘플로 알 수 없음. 단, A·D 이미지를 모델에 넣어 어느 인덱스가 켜지는지 보면 두 클래스 매핑은 **실측 가능** |
| 감정 데이터 | 어노테이터 3명의 얼굴 박스와 감정 라벨 | EmotionNet 크롭 규칙(박스 그대로, 여백 없음) 재확인 |

### 3.2 아직 답이 필요한 것
| # | 질문 | 가정값 |
|---|---|---|
| 1 | Former-DFER 5클래스의 **인덱스 순서**. 학습용 리스트 파일(`train.txt`/`validation.txt`의 `class_idx`)을 만든 쪽만 앎 | 0 집중(F), 1 졸림(S), 2 집중결핍(D), 3 집중하락(A), 4 태만(N) |
| 2 | 파인튜닝 중인 감정 모델의 **구조**는 EmotionNet 그대로인지. 구조가 바뀌면 입력 크기·채널이 달라짐 | EmotionNet 구조 유지, 입력 48×48 흑백 |
| 2-1 | 파인튜닝 모델의 **출력이 4클래스**인지(마지막 층 교체), 아니면 7클래스 그대로인지. 어느 쪽이든 **인덱스 순서**. 백엔드는 7클래스 그대로 받아 1등이 4종 중 하나일 때만 쓰므로 **7클래스 유지도 문제없음** — 파인튜닝이 꼭 필요한지 함께 검토 | 7클래스 유지, 순서 원본과 동일 |
| 3 | 안구 원본 학습 시 얼굴 검출기 종류와 여백 (알면 실측을 건너뜀) | MediaPipe + 20% |

### 3.3 백엔드가 Phase 2에서 실측으로 확정할 것
샘플 데이터가 있으니 AI 팀 답을 기다리지 않고도 아래를 직접 잴 수 있습니다. 결과는 공유합니다.
- **L2CS 크롭 여백**: 샘플 322장에 여백 0%, 10%, 20%, 30%로 크롭해 넣고 `pose.head`의 pitch·yaw와 오차가 가장 작은 여백을 채택.
- **Former-DFER 인덱스**: `condition=A`와 `D` 프레임을 16장씩 묶어 넣고 가장 자주 켜지는 출력 인덱스를 확인. 두 클래스가 가정과 맞으면 나머지 셋도 가정대로 볼 근거가 됨.
- **EmotionNet 회귀 테스트**: 감정 샘플 이미지에 제공 검증 스크립트를 돌려 기대 출력을 만들고, 추론 서버 결과와 일치하는지 자동 테스트.

## 4. 파인튜닝할 때 맞춰 주면 좋은 서비스 조건
모델이 실제로 받게 될 입력은 학습 데이터와 다릅니다. 아래를 알고 데이터를 고르면 실전 정확도가 올라갑니다.

| 조건 | 서비스 실제 값 | 파인튜닝에 주는 의미 |
|---|---|---|
| 입력 해상도 | FE가 웹캠 프레임을 **224×224로 축소**해 보냄. 얼굴 영역은 그중 약 80~120px | 감정 모델(48px)은 축소라 괜찮지만, 시선 모델(448px)은 **4배 확대**가 됨. 파인튜닝 데이터도 얼굴을 100px 안팎으로 줄였다가 쓰면 실전과 가까움 |
| 얼굴 크롭 | **MediaPipe Face Detection** 박스. 감정·집중은 여백 없이, 시선은 20% 여백 | 파인튜닝 크롭을 어노테이터 박스가 아니라 **같은 MediaPipe로** 자르면 서빙과 일치. 검출기 코드는 백엔드가 공유 가능 |
| 프레임률 | 3fps. 집중 모델 16장 = 약 5초 분량 | 학습 클립이 30fps면 프레임 간격이 10배 다름. 집중 모델 정확도가 낮게 나오면 이 원인부터 의심 |
| 카메라·환경 | 노트북 내장 웹캠, 실내 조명, 정면 응시, 안경 착용 가능, 상반신 프레임 | 데이터 선별 기준. 야외·측면·저조도는 우선순위 낮음 |
| 색상 | 감정 모델은 흑백 변환 후 입력 | 색 보정보다 명암·대비가 중요 |

**감정 모델에서 중요한 지표**
서비스 판정이 "불안 확률 0.5 이상이 5초 지속"이라, 4종 평균 정확도보다 아래 둘이 체감 품질을 정합니다.
- **불안의 재현율**: 놓치면 긴장 알림이 안 뜸.
- **중립·기쁨의 정밀도**: 틀리면 리포트의 "안정 표정 비율"이 부풀려짐.
- 당황은 알림 종류가 하나라 정밀도만 적당하면 됨.

**시점**: Phase 2에서 원본 7클래스 모델로 먼저 통합하므로, 파인튜닝 결과는 그 뒤 언제든 교체하면 됩니다. 급하게 맞출 필요는 없습니다.

## 5. 모델을 바꾸거나 재학습했을 때 납품 규약
추론 서버는 아래만 맞으면 코드 수정 없이 모델을 갈아끼웁니다.

1. **파일**: `inference/weights/` 아래에 두고 파일명에 버전 (`l2cs_v2.pkl`).
   git에는 올리지 않습니다. GitHub Release나 Drive로 전달.
2. **구조 코드**: 네트워크 클래스가 바뀌었으면 해당 `.py` 파일도 함께.
3. **전처리 명세**: 입력 크기, 채널 순서(RGB/BGR), 정규화 값, 크롭 여백. 한 줄씩이면 됩니다.
4. **출력 명세**: 클래스 순서, softmax 적용 여부.
5. **성능표**: 어떤 데이터로 몇 % 나왔는지. 이전 버전과 비교.

## 6. 알아 두면 좋은 것
- 제공된 검증 스크립트에는 결과를 보정하는 상수가 들어 있습니다 (정확도 +5, IoU ×3.7 등). 공개 성능 수치를 그대로 믿기보다 팀 웹캠 데이터로 다시 재는 것을 권합니다.
- 제공된 `emotion.py`의 얼굴 검출 분기에 버그가 있습니다 (크롭 대신 원본 전체를 넣음). 참고용으로만 쓰세요.
- 학습 코드는 저장소 `ai/` 폴더에 두고, 데이터셋 원본은 git에 올리지 않습니다 (루트 `.gitignore`에 `*.zip`, `*.pth`, `*.pkl` 등이 이미 제외되어 있음).
