# 01. 설계 개요

## 1. 서비스
웹캠 앞에서 모의 면접을 보면 AI가 **시선·표정·집중 상태**를 실시간으로 보고, 이상이 지속되면 알림을 주고(사용자가 켠 경우), 끝나면 행동 리포트를 준다.

## 2. 구조
```
 사용자 브라우저                    노트북 (로컬)                    노트북 (GPU, Docker)
┌──────────────┐   ① 로그인    ┌──────────────┐
│  FE          │─────────────▶│  Supabase    │  이메일 로그인, PostgreSQL
│  Next.js     │◀─────────────│  Auth + DB   │
│  :3000       │   토큰        └──────┬───────┘
│              │                      │ ④ 저장/조회
│  웹캠 캡처   │   ② REST     ┌──────┴───────┐   ③ JPEG 1장    ┌──────────────┐
│  3fps 224px  │─────────────▶│  BE          │────────────────▶│  추론 서버    │
│              │   ② WebSocket│  FastAPI     │◀────────────────│  FastAPI+Torch│
│              │◀────────────▶│  :8000       │   결과 JSON      │  :9000        │
└──────────────┘  이벤트/리포트 └──────────────┘                 └──────────────┘
```
① FE가 Supabase로 로그인해 토큰을 받는다.
② 토큰을 붙여 BE를 부른다. 면접 중에는 WebSocket으로 프레임을 초당 3장 보낸다.
③ BE는 프레임을 열어 보지 않고 그대로 추론 서버에 넘겨 결과 JSON을 받는다.
④ BE가 결과를 판정해 이벤트를 보내고 DB에 쌓았다가, 종료 시 리포트를 만든다.

## 3. 파트별 책임
| 파트 | 책임 | 책임 아님 |
|---|---|---|
| **FE** | 로그인·회원가입, 웹캠 캡처와 전송, 토스트 표시(사용자 on/off), 리포트 화면 | 모델 결과 해석, 판정 규칙 |
| **BE** | 토큰 검증, 세션 상태, 판정 규칙, DB, 리포트 집계, 추론 서버 호출 | 이미지 처리, 모델 실행 |
| **추론 서버** (BE 담당) | 얼굴 검출, 모델 3개 실행, 결과 JSON | 세션, 사용자, DB |
| **AI** | 모델 학습·검증, 가중치와 전처리 규약 납품 | 서비스 코드 |

## 4. 모델 3개
| 역할 | 모델 | 입력 | 출력 | 서비스에서 |
|---|---|---|---|---|
| 시선 | L2CS-Net (ResNet50) | 얼굴 1장, 448 RGB | yaw, pitch 각도 | 각도 임계값으로 "시선 이탈" 판정 |
| 감정 | EmotionNet (경량 CNN) | 얼굴 1장, 48 흑백 | 7개 감정 확률 | 1등이 중립·불안·당황·기쁨일 때만 사용, 아니면 "기타" |
| 집중 | Former-DFER (트랜스포머) | 얼굴 16장, 112 RGB | 5개 상태 확률 | 2초마다 추론, "집중 저하" 판정 |

시선·집중은 AI-Hub 제공 가중치 그대로, 감정은 AI 팀이 파인튜닝 중. 상세는 `03-for-ai.md`.

## 5. 면접 한 번의 데이터 흐름
```
POST /api/sessions ─▶ WS 연결 ─▶ start ─▶ [프레임 → 추론 → 판정 → 저장 → result/event] × N ─▶ question ─▶ … ─▶ end ─▶ 리포트 생성 ─▶ GET /report
```
- 이벤트 5종: 시선 이탈, 얼굴 사라짐, 긴장 표정(불안), 당황, 집중 저하. 각각 지속 시간과 쿨다운이 있어 같은 알림이 연달아 뜨지 않는다.
- 리포트: 시선 유지율, 안정 표정 비율, 집중 유지율, 알림 횟수, 질문별 지표, 감정 분포(기타 포함), 이벤트 타임라인, 규칙 기반 피드백 문장.

## 6. 갈아끼울 수 있게 만든 지점
| 바뀌는 것 | 고치는 곳 | 다른 파트 영향 |
|---|---|---|
| 모델 없음 → 실제 모델 | `.env` `INFERENCE_BACKEND=mock` → `http` | 없음 |
| 가중치 교체 (파인튜닝) | `inference/weights/` 파일 | 없음 |
| 클래스 순서·이름 | 상수 1개 | 없음 |
| 모델 구조 변경 | 추론 서버의 해당 모델 래퍼 파일 | 없음 |
| 판정 임계값 | `.env` 설정값 | 없음 |
| 추론 서버 위치 이동 | `.env` `INFERENCE_URL` | 없음 |

BE는 `InferenceClient` 인터페이스만 알고(전략 패턴), 추론 서버 안에서는 모델별 래퍼가 입출력 차이를 흡수하며(어댑터), 둘 사이는 JSON 계약뿐이다.

## 7. 용어
| 용어 | 뜻 |
|---|---|
| 세션 | 면접 1회 |
| 프레임 | 웹캠 이미지 1장 (JPEG) |
| 이벤트 | 판정 규칙에 걸린 순간. 토스트를 켠 사용자에게 실시간으로 보이고, 리포트에는 항상 남음 |
| Mock | 모델 없이 규칙적인 가짜 결과를 내는 모드. FE 개발용 |
| 추론 서버 | 모델 3개를 실행하는 별도 Docker 컨테이너 |
