# 00. 요약 보고

## 1. 한 줄 요약
백엔드는 **FE ↔ 세 개 AI 모델 사이의 허브**다. 로그인 토큰을 검증하고, 면접 세션을 관리하고, 웹캠 프레임을 추론 서버에 넘겨 결과를 판정해 실시간 알림과 종료 후 리포트를 만든다. Phase 0(기반 구축과 연결 검증)은 끝났고, Phase 1(세션·실시간·리포트를 Mock으로 완성) 설계가 끝나 구현을 앞두고 있다.

## 3. 확정된 결정 사항과 이유
| # | 결정 | 이유 |
|---|---|---|
| D1 | **추론은 별도 추론 서버**(FastAPI+PyTorch, Docker 필수, 노트북 GPU). BE는 HTTP로 호출만 | 노트북에 RTX 4060이 있어 GPU 활용. BE에 torch를 싣지 않아 가볍고, 모델 교체가 BE와 분리됨. Docker로 누구 PC에서든 같은 환경 |
| D2 | **모델 3개**를 추론 서버 이미지 1개에 함께 올림 | 얼굴 검출을 프레임당 1회만 하고 세 모델에 나눔. 컨테이너·호출·GPU 메모리 모두 1/3 |
| D3 | AI-Hub 제공 Docker 이미지는 **쓰지 않고** 가중치와 구조 코드만 이식 | 제공 이미지는 검증 스크립트뿐, 추론 API 없음. 각 11GB는 OS·conda·PyTorch |
| D4 | **집중 상태 모델(Former-DFER)도 포함**. 시선·감정·집중 3종 | 안구 데이터셋에 딸려 오고 면접 집중도 지표로 가치가 있음 |
| D5 | 감정은 **AI 팀 납품 v2 (4클래스: 기쁨·당황·불안·중립)** 를 `meta.json` 계약대로 사용: 로그확률 + 바이어스 → softmax → τ 0.98 미달은 "불확실"로 보류. 재정규화 금지 (2026-09-07 갱신) | 학습이 클래스 균등이라 중립을 불안으로 28% 오판 → 바이어스로 보정. "확실할 때만 말한다" 정책, 채택률은 FE 에 노출하지 않음 |
| D6 | **실제 배포는 하지 않음.** 노트북 한 대에서 세 서버를 띄우고 같은 Wi-Fi 팀원이 접속 | 팀 규모와 일정. 배포 관련 설계는 참고 절로만 남김 |
| D7 | **Docker는 추론 서버만** 필수. BE·FE는 네이티브 | 환경 재현이 중요한 건 모델 실행뿐 |
| D8 | 토스트 표시는 **사용자가 FE에서 on/off**. BE는 이벤트를 항상 기록 | 꺼도 리포트에 같은 이벤트가 있어야 함. 설정을 BE에 두면 API·상태가 늘어남 |
| D9 | DB는 동기 SQLAlchemy + **SQL 파일 마이그레이션**, 페이지네이션은 limit/offset | 7인 팀에서 누구나 읽을 수 있게. Alembic·asyncpg 학습 비용 제거 |
| D10 | 프레임은 WebSocket **바이너리(JPEG)**, 제어는 JSON. 밀리면 최근 1장만 처리 | base64 오버헤드 제거. 추론이 느려져도 프레임이 쌓이지 않음 |
| D11 | 실시간 프레임은 저장하지 않음. **면접 녹화 영상은 저장** (2026-09-07 변경, 영상 타임스탬프·STT용). 본인만 조회, 세션 삭제 시 삭제 | DB에는 각도·확률 숫자만, 영상은 로컬 디스크 |
