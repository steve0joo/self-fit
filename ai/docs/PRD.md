# PRD: SelfFit AI (모델 파트)

## 목표
모의 면접 웹캠 영상에서 **시선·감정·집중 상태**를 판정할 수 있도록, 세 모델의 가중치와 전처리 규약을 서비스가 바로 붙일 수 있는 형태로 납품한다. 이 중 AI 팀이 실제로 학습하는 것은 **감정 모델 파인튜닝** 하나다.

## 서비스 안에서의 역할
- FE 웹캠(3fps, **짧은 변 224로 축소·종횡비 유지**) → BE → 추론 서버(모델 3개) → 판정 → 토스트/리포트.
- AI 팀은 추론 서버·판정 코드를 만들지 않는다. **가중치와 규약만** 넘긴다.
- 전체 흐름: [`../../backend/guideline/01-architecture.md`](../../backend/guideline/01-architecture.md).

## 납품물
| 모델 | 역할 | 출처 | 학습 |
|---|---|---|---|
| L2CS-Net | 시선(yaw, pitch) | AI-Hub 가중치 | 안 함 |
| Former-DFER | 집중 5클래스 | AI-Hub 가중치 | 안 함 |
| EmotionNet | 감정 7클래스 | AI-Hub 가중치 → 파인튜닝 | **함** |

납품 형식(파일 위치, 전처리 명세, 출력 명세, 성능표)은 [`../../backend/guideline/03-for-ai.md`](../../backend/guideline/03-for-ai.md) 5절.

## 핵심 작업: 감정 모델 파인튜닝
서비스가 받는 입력은 학습 데이터와 다르다. 아래에 맞춰 데이터를 고른다.

| 조건 | 서비스 실제 값 | 파인튜닝에 주는 의미 |
|---|---|---|
| 해상도 | 웹캠을 **짧은 변 기준 224로 축소**(종횡비 유지, 정사각형으로 늘리지 않음) → 비정방형 프레임 그대로 BE 전송 → BE가 그 위에서 MediaPipe 탐지·크롭. 얼굴 80~120px | 얼굴을 100px 안팎으로 줄였다 학습 |
| 크롭 | 원본 종횡비 프레임에서 MediaPipe 박스, 여백 없음 (정사각 왜곡 금지) | 어노테이터 박스 말고 같은 MediaPipe로 |
| 프레임률 | 3fps | 클립이 30fps면 프레임 간격 10배 차이 |
| 환경 | 노트북 웹캠, 실내, 정면, 안경 가능, 상반신 | 야외·측면·저조도 우선순위 낮음 |
| 색상 | 흑백 입력 | 색 보정보다 명암·대비가 중요 |

출력은 **7클래스를 유지해도 된다.** 백엔드가 1등이 **중립·불안·당황·기쁨**일 때만 쓰고, 아니면 "기타"로 버린다(재정규화 안 함). 마지막 층을 4클래스로 교체할지는 선택이다. 다만 백엔드는 확률을 **라벨 문자열**로 받으므로, 납품 시 **인덱스→라벨 매핑**을 함께 줘 `중립/불안/당황/기쁨` 표기가 정확히 일치하게 한다.

## 성공 지표
4종 평균 정확도보다 아래가 체감 품질을 정한다.
- **불안 재현율(recall)**: 놓치면 긴장 알림이 안 뜬다.
- **중립·기쁨 정밀도(precision)**: 틀리면 리포트 "안정 표정 비율"이 부푼다.
- 당황은 알림 종류가 하나라 정밀도만 적당하면 된다.

공개 성능 수치는 검증 스크립트의 보정 상수(정확도 +5, IoU ×3.7 등) 때문에 부풀려졌을 수 있다. **팀 웹캠 데이터로 재측정**한다.

## 범위 밖

- 실시간 서빙 최적화(ONNX 등) — 필요하면 백엔드가 Phase 2에서 검토
